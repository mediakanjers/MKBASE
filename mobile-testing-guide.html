Hoofdstuk 1
Wat is ngrok?
En waarom gebruik je het als developer?

ngrok is een tunneling-dienst — een klein programma dat je lokale server tijdelijk bereikbaar maakt voor de buitenwereld via een publieke HTTPS-URL. Het is de standaardtool in de industrie voor precies dit doel.

Zonder ngrok

Je lokale site (projectnaam.test) bestaat alleen op jouw laptop. Geen enkel ander apparaat kan hem bereiken — niet je telefoon, niet een collega, niet een klant.

Met ngrok

Je krijgt een publieke HTTPS-URL zoals https://abc123.ngrok-free.dev. Elk apparaat ter wereld opent die URL en ziet exact jouw lokale site.

Voordelen van ngrok:

Werkt overal

Thuis, op kantoor, via mobiele data. Geen gedoe met routers of firewalls.

HTTPS inbegrepen

Automatisch beveiligde verbinding, ook al draait je lokale site op HTTP.

Gratis basisversie

Voor lokaal testen meer dan voldoende. Geen betaald abonnement nodig.

Niets op telefoon

Geen app installeren. Gewoon de URL in Safari of Chrome openen.

Eenmalige setup

Installeer ngrok één keer. Daarna werkt het voor elk project automatisch.

Ingebouwd dashboard

Via localhost:4040 zie je alle verzoeken — handig voor debugging.

Hoofdstuk 2
Hoe werkt het?
Het technische plaatje van begin tot eind

Als je ngrok http 80 uitvoert, opent ngrok een uitgaande verbinding vanuit jouw laptop naar de ngrok-servers in de cloud. Wanneer je telefoon de publieke URL bezoekt, loopt het verzoek via die tunnel naar je laptop:

Waarom hoef je geen poorten te openen in de router?
Normaal gesproken moet je voor inkomende verbindingen een poort "doorsturen" in je router naar je laptop. Dat vereist toegang tot de router en werkt niet op elk netwerk. ngrok omzeilt dit volledig: jouw laptop maakt zelf de verbinding naar de ngrok-servers (uitgaand, altijd toegestaan). De router ziet alleen dat jouw laptop verbinding maakt met een server — niet dat er verkeer binnenkomt.

Wat moet er aan de kant van je laptop kloppen?

Apache

Moet de ngrok-hostnaam herkennen en het verzoek doorsturen naar de juiste WordPress-installatie.

WordPress

Moet weten dat de site-URL tijdelijk de ngrok-URL is, anders verwijzen alle links naar projectnaam.test.

HTTPS-herkenning

ngrok handelt HTTPS af maar stuurt HTTP door naar Apache. WordPress moet weten dat het toch beveiligd is, anders ontstaat een redirect-loop.

Hoofdstuk 3
Waarom is dit nodig?
De vijf problemen die ngrok oplost

Je zou denken: even het IP-adres van mijn laptop openen op mijn telefoon. In de praktijk zijn er minstens vijf lagen die dit blokkeren.

1
DNS — ".test" bestaat niet buiten je laptop
Laragon installeert een lokale DNS-server die .test-domeinen vertaalt naar 127.0.0.1. Je telefoon kent die DNS-server niet. ngrok-oplossing: eigen publiek domein dat overal werkt.
2
Windows Firewall — blokkeert inkomende verbindingen op poort 80
Windows Firewall staat standaard geen inkomend verkeer toe van andere apparaten. ngrok-oplossing: verbinding loopt via de cloud, firewall ziet alleen uitgaand verkeer.
3
Router AP Isolation — apparaten kunnen elkaar niet bereiken
Veel routers isoleren wifi-apparaten van elkaar én van bedrade apparaten. Dit is een beveiligingsmaatregel van de router. ngrok-oplossing: verbinding loopt via het internet, niet via het lokale netwerk.
4
WordPress URL's — alle links verwijzen naar de verkeerde URL
WordPress slaat de site-URL op in de database. Alle links, afbeeldingen en scripts verwijzen daarnaar. Als dat projectnaam.test is, kan je telefoon die niet bereiken. ngrok-oplossing: wp-config.php snippet overschrijft de URL dynamisch.
5
HTTPS redirect loop — eindeloos doorsturen
ngrok biedt HTTPS aan maar stuurt HTTP door naar Apache. WordPress ziet geen HTTPS en stuurt door naar HTTPS — wat opnieuw als HTTP binnenkomt. Een eindeloze loop. ngrok-oplossing: wp-config.php snippet vertelt WordPress dat de verbinding al beveiligd is.

Hoofdstuk 4
Installatie — ngrok 1× per computer
Na deze stap hoef je hier nooit meer naar om te kijken
Waarom eenmalig?
ngrok is een globaal programma op je laptop, los van welk project je aan werkt. Je authtoken is gekoppeld aan jouw account en wordt opgeslagen in een globaal configuratiebestand. Installeer het één keer — het werkt daarna voor elk project.
1
Account aanmaken op ngrok.com

Maak een gratis account aan en ga na inloggen naar:

dashboard.ngrok.com/get-started/your-authtoken

Kopieer je authtoken — nodig in stap 3.

2
ngrok installeren via PowerShell (als Administrator)

Open PowerShell als Administrator: klik met de rechtermuisknop op Start → Windows PowerShell (Administrator) of zoek op "PowerShell" in het Startmenu en kies "Als administrator uitvoeren".

winget install ngrok.ngrok --accept-source-agreements --accept-package-agreements

Herstart daarna je terminal. Als ngrok niet herkend wordt, gebruik dan het volledige pad:

C:\Users\<gebruikersnaam>\AppData\Local\Microsoft\WinGet\Packages\Ngrok.Ngrok_Microsoft.Winget.Source_8wekyb3d8bbwe\ngrok.exe
3
Authtoken koppelen
ngrok config add-authtoken <jouw-authtoken>

Token wordt opgeslagen in AppData\Local\ngrok\ngrok.yml. Eenmalig — daarna werkt ngrok altijd.

4
Updaten (alleen als je een foutmelding krijgt over versie)
ngrok update

Hoofdstuk 5
Configuratie — Laragon & Apache 1× per computer
Alle huidige én toekomstige projecten worden automatisch klaargemaakt
Hoe werkt de nieuwe aanpak?
In plaats van elk project afzonderlijk te configureren, gebruik je drie centrale bestanden in C:\laragon\: een vaste Apache-vhost (ngrok.conf) die het ngrok-domein afhandelt, een PHP-prepend-bestand (ngrok-prepend.php) dat WordPress URL's automatisch corrigeert, en een script (ngrok-site.ps1) waarmee je met één commando van site wisselt.

Stap A — ngrok.conf aanmaken (vaste Apache-vhost voor ngrok)

Maak aan: C:\laragon\etc\apache2\sites-enabled\ngrok.conf
Pas NGROK_ROOT aan naar de site die je wilt testen. Gebruik het script (Stap C) om dit automatisch te doen.

# Wijzig NGROK_ROOT om te wisselen van website
Define NGROK_ROOT "C:/laragon/www/mkbase"
Define NGROK_DOMAIN "jouw-domein.ngrok-free.dev"

<VirtualHost *:80>
    DocumentRoot "${NGROK_ROOT}"
    ServerName ${NGROK_DOMAIN}
    php_value auto_prepend_file "C:/laragon/ngrok-prepend.php"
    <Directory "${NGROK_ROOT}">
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>

<VirtualHost *:443>
    DocumentRoot "${NGROK_ROOT}"
    ServerName ${NGROK_DOMAIN}
    php_value auto_prepend_file "C:/laragon/ngrok-prepend.php"
    <Directory "${NGROK_ROOT}">
        AllowOverride All
        Require all granted
    </Directory>
    SSLEngine on
    SSLCertificateFile      C:/laragon/etc/ssl/laragon.crt
    SSLCertificateKeyFile   C:/laragon/etc/ssl/laragon.key
</VirtualHost>

Stap B — ngrok-prepend.php aanmaken (centrale WordPress URL-fix, werkt voor elk project)

Maak aan: C:\laragon\ngrok-prepend.php

<?php
if ( ! defined('WP_HOME') ) {
    define('WP_HOME',    'https://' . $_SERVER['HTTP_HOST']);
    define('WP_SITEURL', 'https://' . $_SERVER['HTTP_HOST']);
    $_SERVER['HTTPS']       = 'on';
    $_SERVER['SERVER_PORT'] = '443';
}
💡 Dit bestand wordt via php_value auto_prepend_file in ngrok.conf geladen vóórdat WordPress start. Het overschrijft de URL voor elk project automatisch — je hoeft nooit meer iets aan wp-config.php aan te passen.

Stap C — ngrok-site script installeren (één commando om van site te wisselen)

Maak aan: C:\laragon\ngrok-site.ps1 (pas $user en $pass aan naar jouw voorkeur)

param(
    [string]$site
)
if (-not $site) { Write-Host "Gebruik: ngrok-site <sitenaam>"; exit 1 }
$sitePath = "C:\laragon\www\$site"
if (-not (Test-Path $sitePath)) {
    Write-Host "Site '$site' niet gevonden. Beschikbare sites:" -ForegroundColor Red
    Get-ChildItem "C:\laragon\www" -Directory | ForEach-Object { Write-Host "  - $($_.Name)" }
    exit 1
}
$conf = "C:\laragon\etc\apache2\sites-enabled\ngrok.conf"
(Get-Content $conf -Raw) -replace 'Define NGROK_ROOT ".*"', "Define NGROK_ROOT `"C:/laragon/www/$site`"" | Set-Content $conf -NoNewline
Write-Host "Ngrok.conf bijgewerkt naar: $site" -ForegroundColor Green
$apache = Get-ChildItem "C:\laragon\bin\apache" -Filter "httpd.exe" -Recurse | Select-Object -First 1 -ExpandProperty FullName
if ($apache) {
    Stop-Process -Name "httpd" -Force -ErrorAction SilentlyContinue
    Start-Sleep -Seconds 1
    Start-Process $apache -ArgumentList '-f "C:\laragon\etc\apache2\httpd.conf"'
    Write-Host "Apache herstart" -ForegroundColor Green
}
# Start ngrok handmatig in een aparte terminal:
# ngrok http --domain=jouw-domein.ngrok-free.dev 80

Maak ook een .bat wrapper aan zodat je geen .ps1 hoeft te typen:

Bestand: C:\laragon\ngrok-site.bat

@echo off
powershell -ExecutionPolicy Bypass -File "C:\laragon\ngrok-site.ps1" %*
Stap D — PATH instellen & Apache herstarten

Voeg C:\laragon eenmalig toe aan je Windows gebruikers-PATH zodat ngrok-site overal werkt. Herstart daarna Apache via Laragon UI. Vanaf nu type je alleen nog ngrok-site mkbase om te beginnen.

Hoofdstuk 6
Per project — geen actie vereist Automatisch
De centrale setup dekt elk project automatisch
Niets te doen

Dankzij de centrale ngrok-prepend.php en ngrok.conf (ingesteld in Hoofdstuk 5) hoef je niets aan te passen in een nieuw of bestaand WordPress-project. Geen snippet in wp-config.php, geen vhost-wijziging, geen Apache-restart.

Hoe werkt het automatisch?
Apache laadt ngrok-prepend.php via php_value auto_prepend_file in ngrok.conf — dat bestand draait vóórdat WordPress start. Het overschrijft WP_HOME en WP_SITEURL dynamisch op basis van de Host-header, en markeert de verbinding als HTTPS. WordPress ziet de juiste URL en genereert alle links, afbeeldingen en scripts correct voor je telefoon.
Nieuw project in Laragon

Maak de site aan zoals gewoonlijk. Typ daarna ngrok-site <sitenaam> in je terminal en test direct op je telefoon.

Bestaand project

Werkt direct. Als er nog een oud ngrok-snippet in wp-config.php staat kun je dat verwijderen — het is niet meer nodig.

Vier stappen, klaar in minder dan een minuut
1
Laragon starten

Zorg dat Laragon draait en Apache actief is.

2
Site wisselen met ngrok-site

Typ de sitenaam die je wilt testen. Het script updatet ngrok.conf en herstart Apache automatisch.

ngrok-site mkbase

Beschikbare sites zien? Typ ngrok-site zonder argument — het script toont alle opties.

3
ngrok starten in een aparte terminal

Open een nieuwe terminal en start de tunnel. Laat dit venster open zolang je test.

ngrok http --domain=urchin-driller-bronchial.ngrok-free.dev 80

Wil je wisselen van site? Typ ngrok-site <sitenaam> in een andere terminal — ngrok blijft draaien.

4
Vaste URL openen op je telefoon

De URL is altijd hetzelfde — sla hem op als bladwijzer op je telefoon.

https://urchin-driller-bronchial.ngrok-free.dev
💡 De URL is altijd hetzelfde dankzij het statische ngrok-domein. Sla hem op als bladwijzer — je hoeft hem nooit opnieuw te kopiëren. ngrok hoeft ook maar één keer gestart te worden per sessie; wisselen van site doe je alleen met ngrok-site.

Checklist per sessie:

  • Laragon draait en Apache is actief
  • ngrok-site <sitenaam> getypt in terminal
  • ngrok http --domain=urchin-driller-bronchial.ngrok-free.dev 80 gestart in aparte terminal
  • Vaste ngrok-URL geopend op telefoon

Van site wisselen tijdens een sessie:

  • ngrok-site <nieuwesite> typen — Apache herstart automatisch
  • ngrok blijft draaien, URL blijft hetzelfde
  • Telefoon herladen — je ziet de nieuwe site

Hoofdstuk 8
Beveiliging Aanbevolen
Toegang beperken tijdens een testsessie

De ngrok-URL is publiek bereikbaar voor iedereen die hem kent. In de huidige setup staat basic auth uit — de URL is direct toegankelijk. Dit is prima voor lokaal testen, maar wees voorzichtig als je de URL deelt.

Basic auth optioneel toevoegen
Wil je toch een inlogprompt? Start ngrok dan handmatig met de --basic-auth vlag in plaats van het gewone commando: 
ngrok http --domain=urchin-driller-bronchial.ngrok-free.dev --basic-auth="gebruiker:wachtwoord" 80
💡 ngrok onderschept de inlogprompt vóórdat het verzoek Apache bereikt — Apache en WordPress worden nooit bereikt als het wachtwoord fout is.

Hoofdstuk 9
Problemen oplossen
Veelvoorkomende fouten en oplossingen
?
"Te vaak doorverwezen" — redirect loop
Oorzaak: WordPress weet niet dat de verbinding al HTTPS is.
Oplossing: Controleer of C:\laragon\ngrok-prepend.php bestaat en de regels $_SERVER['HTTPS'] = 'on' bevat. Controleer ook of php_value auto_prepend_file correct is ingesteld in ngrok.conf en of Apache is herstart.
?
Site laadt maar verwijst nog naar projectnaam.test
Oorzaak: De centrale prepend wordt niet geladen, of er staat nog een vaste define('WP_HOME'...) in wp-config.php die eerder wordt uitgevoerd.
Oplossing A: Controleer of ngrok-prepend.php bestaat en of Apache is herstart na aanmaken van ngrok.conf.
Oplossing B: Verwijder eventuele vaste WP_HOME/WP_SITEURL defines uit wp-config.php van het project.
?
"Server reageert niet" op telefoon
Oorzaak: ngrok draait niet, of de URL is verlopen na een herstart.
Oplossing: Controleer of ngrok actief is in je terminal. Herstart ngrok en kopieer de nieuwe URL.
?
"ngrok: command not found"
Oplossing A: Herstart je terminal na installatie.
Oplossing B: Gebruik het volledige pad:
C:\Users\<naam>\AppData\Local\Microsoft\WinGet\Packages\Ngrok.Ngrok_...\ngrok.exe http 80
?
"Authentication failed: version too old"
Voer uit: ngrok update
?
Afbeeldingen en CSS laden niet op de telefoon
Oorzaak: WordPress genereert nog links naar projectnaam.test omdat de centrale prepend niet actief is.
Oplossing: Controleer of ngrok-prepend.php bestaat, of ngrok.conf de juiste php_value auto_prepend_file bevat, en of Apache is herstart. Controleer ook of er geen vaste WP_HOME define in wp-config.php staat die de prepend overschrijft.
